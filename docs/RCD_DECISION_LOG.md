## D-001 · ROLL 的视觉形态是摄像机自身旋转

- **日期**：起点不明（早于 2026-11-14 的设计圣经）
- **来源**：创作者（总指令 §07、设计圣经 §4）
- **状态**：CONFIRMED
- **结论**：WASD 输入同时产生人物位移与摄像机运动；摄像机不提供自由旋转的主导权（鼠标只做 yaw 修正）。禁止替换为常规的鼠标自由转视角。
- **理由**：这是整个项目的独特性来源，也是宣传语「YOU'LL NEVER TRUST WASD AGAIN.」的兑现方式。
- **实现位置**：`scripts/camera/camera_chase.gd`（唯一 yaw 积分器）、`scripts/camera/camera_rig.gd`（`mouse_look()` 只写 `yaw_offset`，按 `MOUSE_TAU=1.2 s` 衰减）。

## D-002 · 移动方向锚定世界轴，不随镜头旋转

- **日期**：2026-11-19（本轮工程裁决，依据圣经既有硬规则）
- **来源**：设计圣经 §4.2 第 160 行硬规则原文「移动锚定世界轴｜WASD 的移动方向不随镜头旋转而改变；镜头旋转只改变『你看到的世界』，不改变『你按出的方向』」，理由原文「若移动是相机相对，yaw 一转 W 的方向就变，玩家无法建立稳定映射，规则不稳定」
- **状态**：CONFIRMED（文档级硬规则）＋ EXPERIMENT（手感仍待盲测，见 V06）
- **结论**：`CameraMath.move_dir(input_xy)` 只接受输入向量，不接受相机 yaw。旧实现 `scripts/player/player.gd` 里的 `CameraMath.move_dir(ix, cam_yaw())` 已删除。
- **理由（为什么这条不能含糊）**：摄像机 yaw 追随的是**角色朝向**，而角色朝向由移动方向派生。若移动是相机相对，两者会闭成正反馈环——按 W 时「想要的朝向」恒等于相机当前 yaw，误差恒为 0，**镜头完全不转**（招牌机制在最常用的键上失效）；按 D 时误差恒为 -90°，镜头以最大角速度无限旋转、玩家原地绕圈。世界轴锚定把环切断：按 W 就往世界 -Z 走，镜头自己慢慢追上来，玩家能看见「镜头在追我」。
- **代价**：玩家永远无法用「转镜头」来改变「W 的方向」；方向映射是固定的，需要靠关卡与教学让玩家接受。
- **待验证**：圣经 V06 要求 PHASE 2 做「世界轴 vs 角色轴」双版本盲测。本裁决不取消该实验，只确定当前实现版本。

## D-012 · 镜头不参与任何判定，roll 不回馈到任何输入

- **日期**：早于 2026-11-14
- **来源**：设计圣经 §4.2 硬规则（「镜头不参与任何判定」「roll 不反馈」）
- **状态**：CONFIRMED
- **结论**：镜头只是一种观察方式，不改变碰撞、不改变 NPC 行为、不改变可行走区域；roll 是纯视觉量，不参与移动与转向计算（否则玩家会为了「控制 roll」而做无意义输入，规则会变得不可学）。
- **实现位置**：`scripts/camera/camera_math.gd` 里没有任何函数把 roll 作为输入返回给移动或 yaw；`tests/test_camera.gd` 有一条 `roll does not change yaw` 的回归。
- **容易破的地方**：做镜头抖动、命中减速、受伤后晕眩时，如果把这些效果写进 roll 或直接改 yaw，就会破坏这条规则。视觉反馈必须走 `roll_scale` 之类的乘数，且乘数不得进入物理计算。

## D-016 · 片场是「黑暗舞台上的一块布景」，光是高角度的工作光

- **日期**：2026-11-19
- **来源**：工程（真机运行发现），视觉方向由创作者「电影片场」设定推导
- **状态**：PROPOSED
- **结论**：房间外必须有舞台地板（72×60 m 深灰无光泽），主光从 72° 仰角打下来并带软阴影，环境光抬到能保住暗部细节。禁止让镜头直接看到纯背景色的“虚空”。
- **理由（为什么这不是美术润色）**：第一次真机运行暴露两件事——①镜头在 12 m/55° 下必然甩到房间外，没有地板时画面出现一大块黑，玩家会以为贴图丢了；②58° 仰角的主光把每面墙投成一条长而全黑的平行四边形，正好压在门洞与家具旁边，读起来像地上有坑。两件事都会直接影响「能不能看清路线」，而看清路线是 ROLL 与 DIE 的前提。
- **只动表现，不动规则**：主光角度、环境光、阴影参数、舞台地板全部不影响碰撞、判定或 ROLL 参数（D-012 仍然成立）。
- **待定**：地板棋盘格的尺寸与对比度、墙面色温、玩家角色的剪影可读性。这些属于正式艺术方向，等美术样片再定。

## D-023 · relay 主线：五个棚 + 三扇门，趟数由门决定

- **日期**：2026-11-22
- **来源**：创作者全权委托（m00619「按你的想法改造成 85 分以上」）＋十维评审第 4 条（肉鸽结构 48 分）
- **状态**：**CONFIRMED（已实现，等真人试玩调参）**
- **结论**：一局仍是五个棚（`MODULES = 5`），但每个棚之间的三张卡不再是「随便抽一个棚型」，而是三扇门：每张门有自己的棚型、机械条件（`mod`）与**趟数**（`passes` 3 / 4 / 5），趟数多的门返回补给（+1 MARK / +1 CUT / 一片接片）。选门＝用更长的段落换补给，或反过来用短段省时间。

- **数值**：tier 0（首棚）只出 `""`/`fast`（65% 净场）；tier ≥ 2 的深层门给 +1 CUT（不再总是 MARK）。
- **威胁爬升**：`_roll_mod(tier)` 的 hard 概率 `clampf(0.16 + tier*0.09, 0, 0.50)`，越深越容易出现双推轨 / 窄喉。
- **实现位置**：`scripts/relay/relay_run.gd` 的 `_offer_doors()`、`_pick_card()`、`required_passes`、`_stake_label()`；`scripts/relay/relay_rooms.gd` 的 `MODS`。

- **来源**：创作者设计坐标（「不希望它像任何游戏」）＋十维评审第 1 条（「转动要由输入产生」）
- **状态**：**CONFIRMED（数值保守，待真人盲测）**
- **结论**：`CameraRig` 在原有「由 yaw 角速度派生 roll」之上再加一层**由横移与角加速度派生**的 `lean`：`lean_target = -LEAN_CARVE * lateral * |input| - clamp(LEAN_ACCEL * dw, ±1)`，弹簧积分（`LEAN_STIFF 46`、`LEAN_DAMP 12`），上限 `LEAN_MAX = 7.5°`。最终 `roll = drv.roll * roll_scale + lean`。`F3` 一键开关（`tilt_enabled`），关掉即回到 0.2.x 的画面，便于 A/B。reduce_motion 下 lean 恒 0。
- **理由**：原来的 ORBIT 是「时间让画面转」，玩家三十秒就能预测；lean 让**横移这一下**有代价与手感，且与原有 roll 同号（加深而不是抵消）。
- **代价与边界**：满舵横移时总横倾可达 13.4°（原上限 12° 是给派生 roll 的）。lean 只是表现，**不参与任何判定**；`restore_mark_motion()` 会把 lean 与弹簧一起归零，避免读档后镜头歪着。
- **实现位置**：`scripts/camera/camera_rig.gd`（`lean_target`、`_update_lean`、`LEAN_*`）、`scripts/relay/relay_run.gd`（F3）、`tests/test_camera.gd`（`_tilt`）。

## D-033 · 剧组会给这一棚加点东西：三种「事件」，每个只改一个决定

- **日期**：2026-11-22
- **来源**：goals 第 3 条（三种事件节点，每个都改变打法）＋创作者「不像任何游戏」的坐标
- **状态**：**PROPOSED（已实现并逐项截图验证，缺真人试玩）**
- **结论**：每棚开局按种子掷一次事件（第一棚永远不掷，留作干净教学）：`relight` 20%、`extra` 20%、`guide` 12%，其余净场。
  - `relight`：每台推轨顶上挂一盏暖光（`OmniLight3D`，`light_energy 26`、`omni_range 3.8`、`omni_attenuation 0.5`）＋车顶小灯块＋甲板上一块 3 m 见方的暖色光斑。**打法变化**：危险源自己发光，你能远远看见它在哪，但它也把阴影里的路标出来了。

  - `guide`：这一棚的过去自己不碰人（`_physics_process` 里 `if leg_event == "guide": break`）。**打法变化**：它替你示范路线，代价是它不再挡你的路——本棚难度只来自推轨。
- **理由**：三个事件各自只动一件事（可见性 / 密度 / 威胁来源），玩家看一眼就能改打法；而不是叠一层新规则。事件在换场时就广播一句（`_hint`），不等撞上才解释。

- **实现位置**：`scripts/relay/relay_rooms.gd`（`append_room(..., event)`、`OmniLight3D`、光斑 `pool`）、`scripts/relay/relay_run.gd`（`_roll_event`、`_event_line`、`leg_event`、碰撞跳过、存档字段）、`tests/test_relay.gd`（三条事件的断言）。

## D-036 · 死一次，剧组把棚转过来一百八十度（CONFIRMED，2026-11-22）

**决策**：每次死亡（含强制剪回）后，当前这一棚绕自己的中心水平转 180°（`const SET_TURN := PI`、0.45 s）。灯、推轨、地板胶带印、冲线门都跟着转；**幽灵不转**——它继续按录制时的朝向走，于是它的旧路线现在斜穿过新的走法。死亡的那一帧同时印在甲板上（`_drop_photogram()`，0.86×1.42 的淡黄地板印，挂在棚节点下所以随棚转）。

**为什么是 180° 而不是 90°（试过 90° 后改的）**：棚是 9×6。绕中心转 90° 会把半个地板甩到原位之外，而幽灵是按世界坐标回放的——它会被留在棚外的黑暗里，截图里 TAKE 01 躺在虚空上，既读不出也不公平。半转保持同样脚印：地板、幽灵、胶带印都还在甲板上，读作「他们把它反着搭了一遍」，而且和 90° 一样每两次就把朝向翻回去。等棚有了方形脚印（或者字母地形需要不同长宽比时），四分之一转再回来。

**顺带修好的两个真 bug**：①过线判定原来拿世界 x 轴比，棚一转就立刻算过线——改成在棚自己的坐标系里比（`room.to_local(player.global_position).x`）；②`_start_leg()` 的目标点改在棚坐标里构造再 `to_global`，否则棚转过以后目标在世界里是错的。

**实测**：`room.rotation.y` 从 0 到 ±π；死一次 `turned` 自增一次；地板上出现一张淡黄死亡留影；在棚坐标里把玩家送到 local x=9.4 后 `room_pass` 递增、`returning` 翻向，转过的棚里过线仍然成立。

**未解决**：幽灵在转过两次的棚里会走「旧朝向」，视觉上是踩着甲板斜穿；这是设计要的，但还没有真人能确认它读得懂。需要在真机上抓一段录像。

## D-038 路 片场自己会动：一条听棚的传送带，和一个不守规矩的场务（PROPOSED，2026-11-22）

**决策**：事件池加两种，每个只改一个决定。

- `belt`（传送带）：甲板上一条 6.4×1.24 的带子，把人往棚自己的 +X 方向拖，速度 1.6 m/s。玩家顶着走仍能出棚，只是慢（`SPEED - BELT = 1.6`）。
- `runner`（场务）：一个 1.5 m/s 的人沿着棚的 -Z→+Z 来回穿，5.2 m 往返，永不停。撞上就死，死因文案「你撞上了场务。他手里还拿着通告。」
- `goof`（穿帮）：地上一段贴了胶带的方框（半径 0.62 m，白胶带 + 两道红条）。站进去不算被打死，算这条拍废了——同样是一次重来，死因文案「你踩进了画面。这条废了。」
- `key`（绿幕）：一小块绿色方形站位（半径 0.66 m）+ 一块绿幕板。站上去就「不在画面里」：推轨、场务、穿帮胶带、以及你自己的幽灵**全部碰不到你**。它是一个有电影理由的等待位，不是无敌区——时间照走，幽灵照来，你只是可以在这里等一个周期。
- 抢天光（不是事件，是全局的）：每进一节，主光能量 1.0→0.56、色温由 `fff6e6` 往 `ffb877` 走、环境光 0.80→0.60（`_act_light()`）。最后一节是「下午快收工」的光——阴影变长，棚里那盏挂在推轨上的灯变成你真正能读的东西。

**理由**：这两种是「世界在动，而镜头不告诉你」的第一批东西。传送带的关键在实现口径——推力取的是**棚自己的轴**（`room.global_transform.basis.x`），所以 `_rotate_stage()` 转过 180° 之后，同一条带子在世界上自动反向，不需要为「转向」写第二套代码。它同时给了玩家一个可学的判断：站在带上时，先看棚朝哪边，再决定贴哪条边走。场务则是反过来的——他没有任何标记可背、没有规律可背，只能看人，这正是「总有人闯红灯」这句话的机制版。

**实现位置**：`scripts/player/player.gd`（`push` + `set_push()`，`velocity = move_toward(...) + push`）；`scripts/relay/relay_rooms.gd`（`_belts`/`_runners`/`BELT_SPEED 1.6`、`belt_push()`、`crew_at()`、`set_clock()` 驱动场务来回）；`scripts/relay/relay_run.gd`（`_roll_event()` 概率 `belt<0.64`、`runner<0.76`、`_event_short`/`_event_line`、`_physics_process` 每帧 `player.set_push($Rooms.belt_push(...))` 与 `crew_at(...)→_hit(2)`、`_death_line(2)`）。

**实测**：`tests/run_all.gd` **485 断言全绿**（relay 77/77，新增 18 条：带上有推力且无 y 分量、带外为零、无带棚为零、场务一秒移动 >0.4 m、站他身上致命、2.4 m 外安全、无场务棚不致死、胶带区致命、离胶带两米安全、无胶带棚不判穿帮、绿幕站位生效、离它一米半失效、无绿幕棚不生效）；真机站在带中央无输入时 0.8 s 位移 −1.28 m（≈1.6 m/s，方向随棚），场务走到玩家身上 `deaths` 0→1。

**未验证**：传送带与幽灵同场时会不会让人误判「是带子还是幽灵把我推过去的」；场务会不会被读成「随机死亡」（若被这样读，就给他加一个 0.35 s 的转身预备动作，见任务书 §4）。

**实测**：`tests/run_all.gd` **490 断言全绿**（relay 82/82，新增 5 条）；真机站上桥 `player.y == 1.25`、走开回落；截图里能看清桥、两端台阶、桥下的腿，玩家站在桥上，推轨从下面过。

# D-041 · 替身站在轨道上：一个你能押的赌注，而不是一个躲的东西

**状态**：CONFIRMED（已实现、已测、截图确认）。

**机制**：`double` 事件在推轨自己的轨道上留一个替身（浅色身体 + 白脑袋 + 脚下一道红色胶带）。推轨经过他时**停 0.9 秒**再走。玩家能拿这件事做一次判断：站在他旁边等推轨停住再过去，或者不冒险直接绕远。

**为什么是他而不是「替你挨一次」**：替身不该是护盾，而应该是**一件关于剧组的事实**——剧组把一个人留在了轨道上，于是轨道有了一次喘息。它改变的是「什么时候能过去」，不是「能不能被撞死」，和 `relight`（灯光暴露推轨）、`belt`（地面自己在动）属于同一类：只改一个决定。

**实现**：`relay_rooms` 里 `_doubles[room] = {x, z, stall, held, last}`；`_stall_t()` 把 `stall` 从舞台时钟里减掉，`set_clock()` 用扣过的时钟摆车，`hazard_at()` 也用扣过的时钟判定——**看到的车位置就是撞死你的车位置**，否则会出现「车看起来停在远处但你死了」。每次接触最多停 0.9 s（`held` 在离开后清零），所以一辆车不会永远卡在替身身上。

**实测**：`tests/run_all.gd` **493 断言全绿**（relay 85/85，新增 3 条：替身存在、推轨确实会停、暂停后的判定姿态与显示一致）；真机 `stall=0.9 / held=0.9`，截图 `m4_double.png`（紫车停在替身旁边，底下一行「剧组留了一个替身站在那条轨道上。推轨会先撞他，停一拍。」）。

**未验证**：真人是否会等推轨停（这是这一件唯一要问的事）；推轨停下时音乐张力床没有跟着降，可能会让人以为危险解除了——若被这么读，改成 `set_danger` 也跟着 `stall` 走。

# D-043 · 剧组的手艺全上桌：九种事件，后期一棚两件

**状态**：CONFIRMED（已实现、已测、已截图）。

**问题**：D-033…D-041 一共做了九种「剧组对布景做了什么」（relight / extra / guide / belt / runner / goof / key / mezz / double），但**门卡只发前三种**——后六种只有末尾那棚兜底才可能出现。也就是说玩家跑十局也见不到传送带、绿幕、天桥、替身。这不是难度问题，是把做好的东西锁在抽屉里。

**改法**：
1. `EVENT_POOL` 收九个 id；门卡的池子按节切换——**第 1–2 节只发前三种**（先让玩家站得稳），**第 3–4 节发全部九种**。
2. 第 3 节起，两扇非「净场」的门各有一半概率**一棚两件事**（`event` 是逗号串，如 `belt,mezz`）。`RelayRooms.append_room()` 用 `_has(event, id)` 逐个判，几何按件叠加；`relay_run` 只在 `guide`（幽灵不碰人）处需要判成员，其余判定早就由房间自己的 `belt_push/key_at/goof_at/crew_at/floor_height` 直接回答——**所以叠事件没有第二套代码路径**。
3. 提示改成两行：`_event_lines()` 用 `\n` 连起来，`cutting_desk` 的提示条按行数长高、向上叠，不再一行挤成一坨。
4. 顺手清掉 `_event_short` 里 `key`/`mezz` 各写两遍的死分支。

**为什么两个决定可以叠**：D-033 的规矩是「一个事件只改一个决定」。叠两件＝同一棚里同时改两个决定，这是**后期难度爬升**，不是伪难度：它不加快车、不加判定半径，只让你在同一块地上同时处理两件事。第 1–2 节不给，是保证新手期一次只学一个。

**实测**：`tests/run_all.gd` **500 断言全绿**（relay 92/92，新增 7 条：叠事件的棚两件几何都在、仍只跑一台正车、plan 记下 `belt,mezz`、叠棚上传送带仍推人、`key,goof` 两块都在）；真机 `belt,mezz`（天桥 + 甲板传送带同棚）与 `key,goof`（绿幕方块 + 胶带方框同棚、提示两行）两张截图。

**未验证**：一棚两件时**玩家读不读得过来**（尤其 `belt,mezz` 这类叠在视线上的）；如果试玩反馈「看不清」，就退回到「一节最多一次叠，且叠在短场而不是长镜」。

# D-044 · 威亚：一次单向飞行，换掉整条车道

# D-046 · 一局要能从头走到尾，光带也要真的指得进去

- `cutting_desk` 只把**顶部四个数字**（棚、过线、MARK、CUT）与两条细线按比例放大；`_hud` 由 `relay_run._refresh()` 每帧从设置同步。卡片、结算纸、场记板**不跟着变**——那些是你「看」的东西，不是「读」的东西。

**顺手修的 bug**：暂停页 `refresh()` 原来只用 `queue_free()` 清旧行，同一帧重建会把新行叠在旧行上闪一下；改成 `remove_child()` 再 `queue_free()`。

**验收**：暂停页读到 `界面大小：100%`，点一次变 125%，恢复后 `desk._hud == 1.25`、HUD 字与细线同步变大且右对齐仍贴边（截图 `m9_hud125.png`）；`tests/run_all.gd` **515 断言全绿**。

**没做的**：高对比/色盲模式（幽灵已有明度差 ≥25% 与描边，但 HUD 没有专门的高对比皮肤）。

# D-050 · 死在哪、被谁撞的，两件事要同时看得见

**状态**：CONFIRMED（已实现、真机已看）。

**问题**：死亡时有死因字幕（「推轨没有看见你。」「你撞上了第 03 条的你。」），有留影，有场记板——但**死亡发生的那一格从来没有停留在你眼前**：新手档在放板之前就把你送回了检查点，相机跟着你走，死亡地点经常落在板子后面或者干脆在画面外。于是「死得服气」只剩一半：知道被谁撞的，不知道在哪。

**做法**（`scripts/relay/relay_run.gd`）：
- `_hit()` 里死亡瞬间 `_mark_killer(player.global_position)`：在地面放一圈**粉笔白**圆环（外径 1.26 m、内径 1.16 m、无光照、`alpha 0.85`），它比任何道具都大且不是红色——棚里到处是红色道具，红圈会被读成布景。
- 死亡顺序改了：**先放板、先不复活**——`_board_die()` → `_hold_until_board()`（这期间冻结输入与相机）→ `_after_death()` 里等板走完再 `_restore(last_anchor)` + `_rotate_stage()` + `_show_target()`。现在你是在**死亡那一格**上看完 DIE. 卡的。
- 圆环与死亡卡同寿：`_hold_until_board()` 结束、`_start_leg()`、以及新一次 `_mark_killer()` 都会清掉它；它自己也会在 1.5 s 内淡出。

**踩过的两次错**：
1. 第一版是红色圆环 + 锥形箭头。红圈在满棚红色道具里读不出来；而 55° 俯角下 0.3 m 高的锥形在屏幕上就是一个点。
2. 第一版把环放在 y=0.055（甲板面上），玩家正好站在环中心，环被自己的影子与身体吃掉——现在环径 1.26 m，玩家半径 0.32 m，环是**绕着**人而不是**在**人脚下。

**验收**：`deaths` 递增时 `_killer_mark` 存在且 `global_position` 等于死亡瞬间的玩家位置；板播放期间 `player.frozen == true`；板结束后 `_killer_mark == null` 且玩家已回到检查点（截图 `m10_killer8.png`：白色圆环落在死亡点、玩家仍停在原地、底部 DIE. 卡）。`tests/run_all.gd` **515 断言全绿**（此改动纯表现，不新增断言）。

**没做**：没有箭头指向凶手本体。目前「谁」由字幕给、「哪」由圆环给；把两者合成一个箭头需要知道凶手的确切节点（幽灵有、推轨有、场务有、胶带有——四个来源要四种连法），等真人试玩说「看不清是谁」再做。

# D-051 · 颜色不能是唯一的答案

**状态**：CONFIRMED（已实现、断言已过）。

**问题**：两处真·色盲风险，而且都是「生 vs 死」级别：
1. **幽灵的三色**（TAKE 01 青 / 02 琥珀 / 03 品红）是分批色相，红绿色弱玩家最容易混的是琥珀与品红。
2. **绿幕台**是绿色、**穿帮胶带**是红白——这两块一个是安全区、一个是废条区，正好落在最经典的绿/红混淆对上。

**做法**：
- 幽灵地环加**刻痕**（`scripts/ghost/ghost_actor.gd::_build_notches()`）：第 N 条 take 在地环上放 N 个小白块，固定六个方位轮流用（`ang = TAU*i/6 - PI/2`）。所以「这是第几条」可以**数**出来，不看颜色也成立。`setup()` 改 take 号时会重建刻痕。
- 绿幕台加**四角白色括号**（`scripts/relay/relay_rooms.gd` 的 `key` 事件）：它是「方框」而不是「绿色方块」，形状本身就是信息。穿帮胶带本来就是白色胶带围出的方框——这两块现在靠**形状**就能分开。

**验证**：`tests/test_relay.gd` 新增两条——`take_id = 1` 的幽灵恰好 1 个刻痕、`take_id = 3` 的恰好 3 个 → **517 断言全绿**（relay 109/109）。真机截图 `m11_notches.png`（绿幕台四角白括号清楚）；刻痕本身在截图里被字形墙挡住，**没有拍到能数清刻痕的图**——这条靠断言而不是截图。

**没做**：没有做完整的色盲调色板（那要重定世界/幽灵/UI 三层的配色与对比度，属于「美术一轮」而不是「加个开关」）。也不打算给 HUD 加高对比皮肤——HUD 现在只有两组数字与两条线，放大到 150% 已经够读。

# D-052 · 试玩反馈：卡关、看不懂、没有前情提要

**状态**：CONFIRMED（第一轮修完，已真机验证；剧情那一半还没做）。

**试玩里实际发生的事**（内测者原话）：看不懂要干什么；死一次之后「方向键动不了了」；C/M 不知道是干什么的；「感觉过关了没意义」「哪里都很空洞」「没有想继续的心情」；还有一句最要命的——**「你给整个前情提要呗」**。

**第一条是真 bug，而且是连锁死亡**：复活点就是「上一趟停下的地方」，但那一刻推轨可能正压在那儿。玩家复活 → 冻结看板 1.2 s → 解冻 → 0.75 s 后又被同一台车撞死 → 再冻结……体感就是「我动不了」。修法两条：
1. `_clear_spot(pos)`：复活前在 0.5/1.0 m 的十字方向上找一个**当前不在推轨下、不在场务身上、不在穿帮胶带里**的点，最多挪 1.05 m。原地不动仍然是死——但不会是「刚站起来就死」。
2. 复活宽限从 `act_grace`（0.75–1.2 s）提到 `maxf(act_grace, 2.0)`：1.2 s 的板 + 0.75 s 的宽限，对第一次玩的人不够看清自己在哪。

**第二条是教程**。原来第一棚没有任何提示，玩家进场只看到一条亮线和一个白色胶囊。现在按「东西已经在屏幕上了才说」的顺序放五句，全部走同一条提示条（`_first_lessons()`，只在第 1 节、前两棚、PLAY 相位里生效）：
1. 开局 0.8 s：**走到亮起来的那条线。**
2. 第一次回头：**过了。回头，走到另一头那条线。**
3. 第一条幽灵活着时：**迎面过来的是你上一趟的录像。撞上就死。**
4. 第二棚出发时：**按 C 能看一眼自己留下的落点。看片不要钱。**
5. 第三棚出发时：**M 在这里留一个落点。失手会自动回到最近的落点。**
另加两句卡住时最需要的：道具盘打开时**「先拿一件东西，再选下一棚。」**、门卡打开时**「这三张是下一棚。按 1 / 2 / 3 或点一下。」**

**顺手删掉一条**：原来落板后 0.95 s 会弹「四节十二棚。最后一棚要冲线。」——它和上面第 1 句**互相盖掉**（玩家只会看到后说的那句）。一局多长写在标题页开始按钮下面和暂停页里，不在这时候说。

**没做**：剧情与前情提要。试玩里最一致的一句负面反馈是「空洞／不知道为什么打」，而现在的开场只有一句话（「你在补拍一条镜头。棚里的人不会为你停下来。」）。下一版要给的是：一局开始的三行前情、每节换场时场务的一句话、结算页的一句话。这属于内容，不属于机制，所以单独一轮。

# D-053 · 前情提要、一巴掌和一局之后的理由

**状态**：CONFIRMED（已实现、已真机看过画面）。

**来自试玩的三个词**：「空洞」「没有想继续的心情」「你给整个前情提要呗」。这一条只做内容与手感，不加机制。

- **前情提要写在开局板上，两行**：「你是来补拍的。原来那条，废了。／ 棚子每晚换搭，站进镜头的只有几个。」板是最先看的东西，剧情只放在这里和死亡/结算，不另开界面。`slate_board._draw` 现在会**遵守文本里的换行**（以前只按宽度折），所以两句就是两句。
- **一巴掌**：死亡瞬间 `Engine.time_scale = 0.22`，`0.14 s` 真实时间（`create_timer(..., ignore_time_scale = true)`）后回到 1.0。第 0.1 秒的停顿是「打到了」，再长就是卡顿。`_ready` 里强制归 1.0，防止上一局的 hit-stop 活到下一局。
- **过线的回执**：每过一条线一次冷色微闪（`fx.flash(Color("9ceccb"), 0.10, 0, 0.12)`），不响、不出数字。这是你一下午要做几十次的动作，给的是节拍不是奖励。
- **一局之后的理由**：结算页在「走得最远的一次」时才多一行——`best_set` 是这游戏**唯一**跨局保留的东西。没有树、没有货币、没有解锁，进步就是你走得比上次远。

**没做**：真正的剧情线（谁在拍、为什么要补、补不完的原因都没有实体）、角色、对白。这一版是「一句话前提 + 三个位置的说法」，不是叙事。

# D-054 · 五种棚是五个地方，地上有通告

**状态**：CONFIRMED（已实现、真机看过）。

**问题**：五节十二棚，棚型只改墙的位置和颜色——玩家走完一局记不住自己去过哪。这是「模板刻出来的」那种观感，不是内容不够。

**改法（只动外观，不动任何判定）**：`relay_rooms._dress(room, kind, ink, variant)` 给每个家族一套家具与一条地面漆带：

| 家族 | 房间长什么样 |
| --- | --- |
| I 条 | 两根灯架（顶上黄灯）+ 一条电缆槽 |
| L 拐 | 堆在角落的木箱、一只矮箱、一根铁柱 |
| O 环 | 待拆的脚手架（三根立柱 + 一道横梁）+ 一块幕布 |
| H 双道 | 顶上的吊轨 + 三袋沙配重 + 一只木箱 |
| S 双弯 | 一根通风格栅 + 一块「从前有台机器」的地面漆 |

漆带用该家族的颜色压暗 35%，位置在 `z = ±2.62`（走道外侧），所以它只告诉你「这是哪一族」，不挡路。

**再加一件：地上的通告**。每棚远端走道外侧放一张纸 + 一盏小灯（`Vector3(7.25, .014, 2.24)`），走上去就出现一句话，一局只出现一次（`_notes_read` 按棚序号记）。四句话按「这一节」取，全部是剧组公文口气：
1. 通告：今天补第一条。上一条被剪了，剪的人没留名。
2. 地上那圈胶带是昨天的走位。标得比你准。

4. 门那头是交货口。过线，这一卷就不是你的了。

这是这游戏**唯一**的叙事：没有对白、没有菜单、没有过场，只有留在甲板上的纸。走快的人会错过。

**没做**：棚型几何（房间还是 9×6 的长条，只是内部不同）、每家一套音乐、道具换外观。这三件都还要做，但先把「记不住」这一条补上。

# D-057 · 第一间不是长方形的棚：L 的侧龛

**状态**：CONFIRMED（已实现、真机站进龛里看过）。

**为什么**：五族十二棚全是 9×6 的长条，只有墙内部不一样——这是「模板刻出来的」。真正让一间屋子有性格的是**平面本身**：有没有地方可以躲，有没有一眼看不到的角落。

**做法**（只动 L 一族，先做一间看会不会塌）：L 棚的侧墙不再是一整片，而是在 `x 3.0…6.0` 开一个 3 m 的口，墙后长出一个 1.52 m 深的龛（地板 + 三面墙 + 开口上方一条白漆过梁）。`hand` 决定龛开在哪一侧，所以同族两趟看到的是不同的角落。

**它有什么用**：推轨只在 `|z| ≤ 2.24` 之间扫，龛在 `z 2.94…4.46`——**站在龛里，车永远撞不到你**。这不是新规则，是几何给的：有了异形平面，才第一次出现「不靠宽限、不靠绿幕也能安全站住」的地方。它也让「等一个周期再走」这个动作有了固定位置。

**没做**：过线判定和光带仍假设一条直线（`SET_LENGTH` 硬编码），所以这一轮只敢在**侧向**开龛，不敢改出口位置。下一步是把「这一间的出口在哪」变成房间自己报的值（`exit_x()`），然后才敢做空壳（出口在侧面）与中央岛（绕行）。

# D-058 · 房间自己报门在哪，于是第一间「空壳」出现

**状态**：CONFIRMED（526 断言全绿，真机验证门点与光带）。

**改动**：`scripts/relay/relay_rooms.gd` 每间棚登记一份 plan：

```
_plans[i] = {"entry": Vector3, "exit": Vector3}
```

`relay_run` 不再用 `SET_LENGTH - 0.1` 猜门在哪，而是问房间：走路目标取 `plan["exit"]`（回程取 `plan["entry"]`），过线判定改成 `$Rooms.crossed(pos, room, returning)`——到**门点**的 XZ 距离 ≤ 1.35 m。1.35 就是那条粉笔线自己的长度，所以「过线」现在真的等于「踩在那条线上」，而不是「走过房间任一处的某个 x」。

**第一间空壳**：I 族的 plan 变成**斜穿**——进低（z = −1.60）、出高（z = +1.95），光带跟着挪到 z = 1.95、只有 2.1 m 长。玩家不再走中线，而是从一角斜着穿过整间棚。

**先钉后改**：`tests/test_relay.gd` 先加 8 条断言把直线房间的行为钉死（entry x=0、exit x=9、exit z=0、站在线上算过、差 2 m 不算、回程在近端结束），再加空壳的两条（远端线在 z=1.95、中线不再是门）。这样后面任何 plan 都不能悄悄把终点从光带底下挪走。

**代价**：过线不再覆盖整间棚的宽度——站在 z=±2.9 的角落跨过 x=9 不算过线，必须走到线上。这是有意的：线画在哪里就该在哪里过。

## 变更规则
1. 新增决策 → 追加条目，编号连续，不得改写历史条目。
2. 推翻旧决策 → 新条目 + 在旧条目上标 `SUPERSEDED by D-0xx`，保留原文。
3. 只改实现不改决策 → 只更新条目里的「实现位置」。
4. 任何标 CONFIRMED 的条目被改动，必须在会话里向创作者说明改动内容与理由。
