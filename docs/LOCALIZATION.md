# 本地化（LOCALIZATION）

中文是开发语言，也是权威版本。英文是完整本地化，不是附赠。任何语言切换都不改变游戏状态、判定、结局；只换字。默认显示哪种语言由实现决定，本文件只规定：任何受支持语言都必须是完整文案。

## 1 · 两种语言的地位

- `zh`：开发语言。所有文案先用中文写，中文定稿后英文再写。中文改了意思，英文必须跟着改，不允许英文停在旧版本上。
- `en`：完整本地化。每个玩家可见的字符串都有英文，不存在"英文缺这一句，回退到中文"。缺了就是 bug。
- 结构上两者对等：`{"zh": "...", "en": "..."}`，没有主从字段，没有"默认语言"的隐式回退。
- 英文不是逐字翻译。必须像英文写出来的，长度必须和中文相当；变长就是没译好。

## 2 · 文本放在哪

- 全部放在 `data\*.json` 里，每个字符串都是 `{"zh", "en"}` 对。案件在 `data\case.json`（schema 见 CASE_AND_ENDINGS.md），其余文案建议放 `data\strings.json`（可按界面拆成多个 json），按 §4 分组。
- 禁止在 `.gd`、`.tscn`、主题资源里硬编码任何玩家可见文字。包括临时占位、调试文本、`Label.text = "..."`。一个都不行；要加字，先加到 json。
- 禁止把文案写进代码注释再"以后提取"。
- `.gd` 只允许出现 id 或 JSON 路径，例如 `tr("slate.word.cut")`。

## 3 · 稳定 id 与稳定路径

- 每个可见字符串必须有稳定 id。id 一经使用不再改，改文案不改 id。
- 用 JSON 路径引用的字符串（例如 `case.json` 的 `npcs[0].lines[1].text`），路径本身就是 id，一旦发布不能重排数组。
- 变量用 `{name}` 占位，不允许拼接字符串，例如 `死于第 {take} 条` / `DIED TO TAKE {take}`。同一句话在两处显示，用同一个 id。

## 4 · id 命名约定

| 前缀 / 形态 | 用途 | 例子 |
|---|---|---|
| `ui.menu.*` | 主菜单 | `ui.menu.start` |
| `ui.hud.*` | HUD 与提示 | `ui.hud.hold_to_take` |
| `slate.word.*` | 场记板大字 | `slate.word.cut` |
| `slate.field.*` | 场记板四格 | `slate.field.take` |
| `slate.call.*` | 口令 | `slate.call.action` |
| `slate.subtitle.*` | 声音字幕 | `slate.subtitle.clack` |
| `death.cause.*` | 死因 | `death.cause.stagehand` |
| `report.*` | 报告卡 | `report.stance.file` |
| `verdict.*` | 判定文本 | `verdict.file_closed.body` |
| `take.*` / `outtake.*` / `ending.*` | 条数、花絮、结局 | `ending.truth.body` |

- 全部小写，层级用点，层级内用下划线。
- 不在 id 里写语言、版本号、`copy2`、`new`、`final`。
- 同一前缀下保持一种词序即可。

## 5 · 新增一种语言

1. 在 `data\strings.json` 与 `data\case.json` 里，把每个 `{"zh","en"}` 扩成三元组，键用 ISO 639-1（`ja`、`fr`）。
2. 语言表登记 `zh`、`en` 与新增语言。中文仍是开发语言，不删。
3. 跑校验：所有 pair 的键集合必须完全相同，不允许某个对象只有两种语言。
4. 字体必须带新语言的字形覆盖（见 §6），否则不允许上线该语言；长度规则按新语言重测一遍。
5. 新增语言不改任何代码路径、不改任何 id。

## 6 · 字体（硬性要求）

- Godot 默认字体不覆盖中日韩字形。中文出现在任何界面之前必须换成带 CJK 覆盖的字体，不换就是满屏方框。这是硬性要求，不是建议；禁止用系统默认字体兜底，兜底等于不可控。
- 中文必须覆盖 GB2312 全集（6763 字）+ 常用标点（，。：；！？、·「」《》——…）+ 全角括号与引号。验收前把 `data\*.json` 里出现的所有汉字导出成字表，逐字比对。
- 英文必须覆盖 ASCII 可见字符 + 常用标点（`' " — …`）。`ROLL.` / `CUT!` / `DIE.` / `RETAKE?` 全大写，字体要保证大写字母宽度一致。
- 场记板字段（`SCENE`、`TAKE`、`DIRECTOR`、`CAMERA`）用等宽或半等宽字体，保证 `01` 与 `03` 不跳宽。
- 中英混排时字体族按语言切换；同一界面不混用，除非是刻意设计的场记板等宽字段。

## 7 · 长度与溢出

场记板大字区（1080p 下 480×200）：

| 语言 | 上限 | 超出怎么办 |
|---|---|---|
| 中文 | 6 个汉字 | 缩到 0.7 倍；再超就是文案写错，改文案 |
| 英文 | 10 个拉丁字符 | 同上；不允许换行 |

- 场记板永远单行。`ROLL.`（5 字符）、`CUT!`（4）、`DIE.`（4）、`RETAKE?`（7）都在上限内；新增口令不得超过 10 字符。
- 场记板四个字段：值固定两位，字段名不超过 8 个拉丁字符或 4 个汉字。
- HUD 提示：中文不超过 16 个汉字，英文不超过 40 个字符，最多两行；放不下就改文案，不允许缩到 20px 以下。
- 报告卡标题一行，正文最多四行；中文每行不超过 24 字，英文每行不超过 52 字符。
- 一律禁止截断加省略号。宁可缩字号，宁可改文案，不可截断。
- 交付前用最长文案跑一遍：中文 `重拍？`、`死于场务`，英文 `DIED TO STAGEHAND`、`RETAKE?`，确认不溢出。

## 8 · 语气：该做与不该做

这一款的声音是冷的、简短的、荒谬的、带一点嘲弄，词汇来自片场。没有人物解释设定，没有人物说出主题。

该做：

- 用片场口令与动作词：开机、卡、重拍、走位、连戏、收工、这条过了。
- 让句子短。一行能说完的，不写两行；能删主语就删。
- 让荒谬感来自事实本身，不来自感叹号。`他昨天也这么说。` 比 `他居然又这么说！！` 好。
- 英文用行业里的真词：`CUT.` `TAKE 02` `SAME NOTE AGAIN.` `WE'LL GO AGAIN.`
- 冷句配热行动：说话的人越平静，玩家越不安。

不该做：

- 不解释笑点。嘲讽写在事实里，不写在括号里；留歧义，不要求读者必须读懂。
- 不写"原来……""这意味着……""其实你早就……"这类揭示句，也不给角色加情绪形容词。
- 不用血腥、内脏、尖叫。死亡只有一记 CLACK 和一行字。
- 不把英文写长。英文比中文长一截就是没译好，回头再压。
- 不给同一句中文写两个英文版本（"正式版""轻松版"）。一个 id 一个译文。
- 不在文本里提"游戏""玩家""存档""重开"；不用网络梗、流行语、表情符号，这些半年后就过期。
